# Copyright in India: how ReOpSy stays registrable without dropping features

This is a practical checklist, not legal advice. Have an IP lawyer review it before you file, because the rules on
AI-assisted work are still moving.

## 1. What copyright protects, and what it doesn't

| Protected (yours) | Not protected (free for anyone, including you) |
|---|---|
| Your source code, as a literary work and computer programme under the Copyright Act, 1957 | Ideas and features: follow, circles, streaks, feeds, recommendations, reactions |
| Original UI text, onboarding copy, guidelines, docs | Mechanics borrowed from LinkedIn, WhatsApp or Duolingo |
| Original graphics, icons and illustrations you make | Facts and paper metadata (titles, authors, DOIs) |
| The selection and arrangement of your design | Short phrases and common UI patterns |

**What this means for features:** you can build every social idea from big apps (follow, groups, reactions,
notifications). What you can't do is copy their code, logos, icons, illustrations, exact screen designs or brand names.
ReOpSy's UI is its own design system (`app/src/ui/`), and its icons come from Feather (MIT licence).

## 2. Human authorship when you build with AI

- **The rule:** the Copyright Office requires a human author. An AI system cannot be named as one.
- **AI-assisted work can still be registered** when a human made the creative decisions. The 2026 DABUS decision held that
  AI-generated work can be "original", but authorship must go to a person.
- **Name yourself as author on Form XIV.** You conceived the product, chose the features, directed the design, and reviewed,
  edited and accepted the code.
- **Keep the evidence:**
  - the git history
  - pull-request descriptions
  - `docs/replan/` (your requirements and decisions)
  - the prompts you wrote
- **Commit under your real name.** Recent commits are authored as "ReOpSy Bot". Run this once:

  ```bash
  git config user.name "Your Full Name"
  ```

  ```bash
  git config user.email "you@example.com"
  ```

- **Be truthful:** if the form or an examiner asks whether software tools (including AI) were used, say so. Using tools does
  not remove your authorship of the decisions you made.

## 3. Third-party code and content

- **Dependencies:** almost all are MIT, Apache-2.0, BSD or ISC. Run `node scripts/third-party-licenses.js` before each
  release. It writes `THIRD_PARTY_NOTICES.md` and flags any GPL, AGPL or other copyleft licence. Keep that file in the repo
  and link it from the app's About screen.
- **The deposit:** it contains only your code. `scripts/make-copyright-deposit.js` skips `node_modules`, build output and
  lockfiles.
- **Legacy tests:** the root `tests/` folder was generated by earlier agent sessions. Exclude it from the deposit, or
  review it so you can stand behind it as your work.
- **Paper content:**
  - arXiv metadata and OpenAlex data are CC0.
  - Abstracts can belong to publishers. ReOpSy shows its own short summaries and links out.
  - Never host PDFs.
  - Summaries are labelled "AI-written".
- **User posts:** users keep copyright in what they write. The Terms grant ReOpSy a licence to display it. Plagiarism and
  copyright reports go through the in-app Report button and the takedown address.
- **Other products' names:** Zotero, Overleaf, ORCID and arXiv are used only to name integrations ("Send to Zotero"). No
  logos, and no claim of endorsement.

## 4. Filing checklist (Form XIV, computer programme)

1. **Stabilise a version.** Tag it, for example `git tag v2.1.0`.
2. **Generate the deposit:** `node scripts/make-copyright-deposit.js`. Read `dist/copyright/SECRET-SCAN.txt`. Every finding must be a test
   fixture or placeholder, never a real key.
3. **Make the PDF:** open `dist/copyright/deposit.html` and print it to PDF.
4. **File online:** at copyright.gov.in, file Form XIV under "Computer Software / Computer Programme".
   - **Fee:** ₹500 per work.
   - **Statement of Particulars:** you are the author and owner.
   - **Publication:** state whether the work is published (on the Play Store or the web) and give the date.
5. **No-objection letters:** needed only if someone else wrote part of the code.
6. **Keep the Diary Number.** Answer any discrepancy letter promptly.
7. **Later versions:** a major new version is a new work. File again when it changes substantially.

## 5. Related protections, optional and within budget

- **Trademark "ReOpSy":** a search and filing in classes 9 (software) and 42 (SaaS) costs roughly ₹4,500 per class for
  individuals and startups. Copyright does not protect a name; a trademark does.
- **Repository visibility:** the GitHub repo is public. Public code is still protected by copyright, but anyone can read it.
  Make it private before commercial launch if you don't want competitors studying it.
- **No LICENSE file:** the repo currently has none, which means "all rights reserved". Add one only if you decide to open-source
  parts of it, for example the ingest pipeline.

## 6. In-app notices (already in this build)

- AI-written label on every generated summary (India IT Rules 2026 amendment, Play AI-content policy).
- Community guidelines, reporting, blocking, and a grievance-officer contact (IT Rules 2021, Rule 3).
- Account and data deletion, and data download (DPDP Act; Play account-deletion policy).
- Data-source credits on the You screen.

Set `EXPO_PUBLIC_COPYRIGHT_HOLDER`, `EXPO_PUBLIC_GRIEVANCE_EMAIL` and `EXPO_PUBLIC_TAKEDOWN_EMAIL` before release, so the
app shows your name and contacts.
